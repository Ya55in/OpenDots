# Downloadable documents

Ask a Dot to create a PDF, Word document, Excel workbook or PowerPoint. The `generate_document` server tool creates real files and returns authenticated download cards in the conversation. Existing assistant responses also have **Export file**. Files remain available in **Space → Files & storage**, scoped to their Dot. Connected Drive storage receives future generated files in that Dot's folder; otherwise originals are stored locally. No Google connection or external document-generation service is needed.

Supported formats: PDF, DOCX, XLSX, PPTX, Markdown, plain text, CSV. PDF and Word accept Markdown headings, paragraphs, lists, quotes and tables. Excel creates an overview sheet plus a separate sheet for each table; numbers stay editable and headers are frozen. It does not infer or calculate financial formulas. CSV requires one table and escapes formula-like content. PowerPoint turns sections into editable slides and splits content conservatively across slides. This is a deterministic document renderer, not arbitrary code execution.

Styles: executive, minimal, proposal; automatic VYANIS/VIGON brand labels and accent colors from the Dot name, with explicit brand/accent overrides through the generation tool. No logos, signatures, factual claims or pricing are invented by the renderer. The agent must use approved sources and applicable imported skills. Color contrast, text wrapping, repeated PDF table headers, Word heading styles, page numbering, and bounded slide content make common business documents readable. Very wide tables or overfull slides return actionable errors rather than silently discarding content. The source text stays searchable as file memory.

Limits: 100,000 source characters, 25 MB per file, 150 PDF pages, 100 slides, 45 seconds per format, two rendering workers with bounded heaps. PDF embeds Liberation Sans (supplied under its license by pdfjs-dist) for French/English and covered characters; unsupported glyphs return a clear error and DOCX remains an alternative. Images are captions only: this first version does not insert uploaded logos/photos or generate charts. Office files remain editable; exact layout depends on the viewer's fonts. Automated content/layout checks do not certify factual accuracy or replace visual review for final customer deliverables.

Worker code never executes user Markdown/HTML or fetches its URLs. Raw HTML is rejected. Output filenames are sanitized. Generation is restricted to the Dot's authorized Space and conversation; authorization is checked again after rendering and before saving. Retry of identical content/formats within a conversation reuses the generated files. Partial successes are returned with per-format errors. Local source snapshots survive Drive disconnection, following the same storage rules as attachments. All downloads require existing owner authentication; no public links or access tokens are embedded.

Validation covers actual binary signatures, PDF text and page counts, DOCX/XLSX/PPTX text extraction, editable numeric spreadsheet values, long-table pagination, cancellation, authorization boundaries, retry behavior, Drive persistence, API authentication/origin enforcement, and download-card rendering. Sample PDFs and converted Word/PowerPoint files are also visually reviewed during development.
