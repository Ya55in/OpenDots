# Original Word templates and document previews

When a user refers to an existing order, proposal or branded document, Dots can find the original `.docx` in their own file library or in verified migrated archives. Archive lookups use bounded random access to SQLite chunks; they do not unpack the whole archive or write archive paths to disk.

The agent workflow is `find_word_templates` → `inspect_word_template` → `edit_word_template` → `review_document`. Text edits address an XML part, paragraph number and exact unique old text. Runs retain their formatting; unchanged package parts retain their original bytes. Header/footer text and table cells are supported. This is a text-editing workflow; adding rows, changing drawings and rewriting fields or tracked changes is not yet supported. Prefer unsigned drafts and never treat an old signature as authorization to sign a new document.

The downloadable PDF is rendered from the edited DOCX with LibreOffice. Poppler creates page images. The chat and file library offer authenticated Preview buttons, navigation and review observations. The configured reasoning model reviews the actual page images in batches; `DOCUMENT_REVIEW_MODEL` can select another vision-capable model on the same configured provider. A review applies to the SHA-256 digest of the file, checks every page, and is only saved after every batch succeeds. Visual review does not verify business facts or guarantee perfection. Agents must read observations and revise reported problems.

Runtime packages are installed by `railpack.json` and the app Docker image: LibreOffice Writer, Poppler, fontconfig, Carlito, Caladea, Liberation, DejaVu and Noto fonts. DOCX retains original font declarations; PDF font substitutions are reported explicitly. For exact proprietary font fidelity, install the appropriately licensed original fonts in the server image. Do not silently promise pixel-identical Microsoft Word rendering.

Limits: DOCX/PDF 25 MB, expanded Word package 80 MB/2,000 entries, two concurrent render jobs, 60 seconds per native command, 30 pages/20 MB of previews per document, 50,000 entries per migrated archive. Macros, external resources other than HTTP(S) hyperlinks, DDE fields, embedded objects and digitally signed packages are rejected. Rendering uses private temporary directories, isolated LibreOffice profiles, disabled macros and link updates, restricted child-process environment, and no shell-interpolated document values. Temporary files are removed after success or failure.

Files save to the Dot's connected Google Drive folder, or local Space storage. If PDF rendering fails, the edited DOCX remains downloadable and the tool reports the failure. Failed visual review never becomes a successful review badge. Original files are never overwritten.
